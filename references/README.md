# Visual references

These files help compare the character and plan future surfaces. They are not
the token source or a promise of shipped features. The
[asset manifest](../assets/manifest.json) records their origin and status.

- `website/`: supplied landing and documentation concepts. Layout and atmosphere
  are useful; versions, statistics, APIs, social destinations, dependency
  statements, and license footers are unverified concept copy.
- `ecosystem/`: 14 package illustrations, including `event-dispatcher`, `fork`,
  `agents`, `changelog`, `clock`, `composer-installers`, `config`, `container`,
  `defer`, `github-actions`, and `iterators`, alongside `framework`, `dev-tools`,
  and `enum`. Three files match pinned public default-branch commits; one is
  tracked on a local task branch and ten were locally supplied untracked files.
  The manifest distinguishes these sources. The developer hoodie family is
  useful character context; banner code and claims need separate verification.
  Violet eyes in Enum are a historical deviation, not a new character rule.
- `icons/`: archived icon collection/sprite for reference. These SVGs contain
  vector geometry, but third-party marks and authorship have no recorded usage
  rights. The sprite CSS now points to the actual `icon_sprite.png` filename;
  that repair is recorded as a derivative. Prefer accessible labeled icons from
  a documented source when implementing a production interface.

The 2026-10-03 audit inspected 19 local image paths / 16 distinct contents.
Fourteen source illustrations were curated; ignored generated duplicates and
older divergent renderings were not imported. The original cute source-pack
exports are archived in the ignored local `backup/dash/legacy-kit/`. Newly
created Dash reference collections live in `assets/mascot/` instead.

editorial collections. The [assessment](../docs/brand/assessment.md) records
remaining design work and provenance limits.
