# Contributing to PHP Fast Forward

Contributions to PHP Fast Forward are welcome: bug reports, documentation, examples, package improvements, and visual identity work. These are organization defaults. Follow the affected repository's own contribution guide, operating instructions, and documented checks when present.

## Choose the right repository

Search the affected repository's issues before opening a proposal. Describe the problem or reader need, the expected result, and enough evidence to understand it. Framework code and package documentation belong in the relevant package repository.

The [organization profile and design repository](https://github.com/php-fast-forward/.github) maintains public profile content, design assets, and shared community metadata. File brand and mascot requests there, even if this guide or an inherited template appears in another repository.

Follow the [community Code of Conduct](https://github.com/php-fast-forward/.github/blob/main/CODE_OF_CONDUCT.md). Use the affected repository's security policy, or the [shared security guidance](https://github.com/php-fast-forward/.github/blob/main/SECURITY.md), for potential vulnerabilities.

## Prepare a contribution

Small corrections can go directly into a pull request. For a broad API, architecture, or visual direction change, explain the intended result before building a large implementation.

Keep changes focused. Explain what changed and why, link a related issue when one exists, and include the relevant checks and their results. Use the affected repository's documented environment and test commands. Add regression coverage when it meaningfully verifies a behavior change. Describe manual review and limitations where automation cannot verify the result.

Use public, sanitized material in examples, screenshots, and logs. Exclude secrets, personal data, private links, and content you are not authorized to publish. Keep operating-system files, editor metadata, and unrelated changes out of the diff.

## Brand and asset contributions

For work in the design repository, read [DESIGN.md](https://github.com/php-fast-forward/.github/blob/main/DESIGN.md), [STYLE.md](https://github.com/php-fast-forward/.github/blob/main/STYLE.md), [SOUL.md](https://github.com/php-fast-forward/.github/blob/main/SOUL.md), and [the asset guide](https://github.com/php-fast-forward/.github/blob/main/assets/README.md). The [asset manifest](https://github.com/php-fast-forward/.github/blob/main/assets/manifest.json) records asset identity, origin, and reuse status.

Keep editable sources, references, and reusable exports identifiable. Record the origin, author or generation method where known, transformations, and permission or license status. Mark unknown information explicitly. Storage in the repository does not itself grant reuse rights, and a repository license must not be assumed to cover every illustration, font, logo, or reference.

For a visual pull request:

- Explain the intended audience and surface.
- Follow the design, style, and character contracts, or identify a proposed contract change.
- Include a preview at the intended size, with light and dark surfaces where relevant.
- Preserve the fox's recognizable features and provide alternative text when the image carries information.
- Update `assets/manifest.json` and the asset guide for new or changed assets.
- Include source and permission information, dimensions, and relevant validation results.

Maintainers review scope, consistency, evidence, and reuse status. A new visual concept remains a proposal until it is accepted into the documented identity. Each repository's maintainers decide whether a contribution is ready to merge.
